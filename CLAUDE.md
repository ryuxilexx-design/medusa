# Med.uz.ai — clinic management platform (demo MVP)

Product name in every UI text, document and export: **Med.uz.ai** (old name "Meduza" survives only in internal identifiers: `@meduza/*` packages, `meduza_session` cookie, `meduza.branch` storage key, DB/container names — do not rename those). UI languages: Uzbek Latin (source text), Uzbek Cyrillic (derived automatically) and Russian — chosen per person (see i18n below). In Uzbek use the typographic apostrophe `‘` (o‘, g‘) and `’` (ma’lumot), never ASCII `'`. Spec: `docs/MVP_TZ.md`; status and limits: `docs/DEMO_STATUS.md`; meeting runbook: `docs/DEMO_SCRIPT.md`.

## Layout

- `apps/api` — NestJS 11, prefix `/api/v1`, raw SQL via `pg` (no ORM). Controllers in `src/modules/*`, cross-cutting code in `src/core/*`.
- `apps/web` — Next.js 15 App Router, all pages are client components using TanStack Query; `/api/v1/*` is proxied to the API (`next.config.mjs` rewrites), so the browser never talks to :4000.
- `packages/contracts` — zod schemas, labels, money/phone helpers shared by API and web.
- `database/` — SQL migrations (`migrations/NNN_*.sql`, applied on API start), deterministic seed (`seed/build.ts`), reset/clock helpers (`src/index.ts`).
- `e2e/` — puppeteer-core scripts with the system Chrome; `run.mjs` starts an isolated stack.

## Commands

`npm run db:up` · `npm run start` (prod build, web :3000 / API :4000) · `npm run dev` · `npm run build` · `npm run typecheck` · `npm test` (118 API tests; `test/ops.test.mjs` = health, sliding sessions, body limits, CLI password reset; `test/audit.test.mjs` holds the regression tests of the 2026-10-20 audit — `docs/audit/`) · `npm run e2e` · `npm run db:reset` (wipes live demo data — needs explicit user intent) · `npm run db:backup` / `db:restore -- <file>` · `npm run db:readonly-role` · `npm run db:create-clinic -- …` (onboard a real clinic; prints a one-time temp password) · `npm run db:reset-password -- --login <phone|username> [--tenant <name|id>]` (operator's reset when the sole manager is locked out: new temp password shown once, lockout cleared, sessions closed) · `npm run db:import-icd10 -- file.csv` (official MKB-10 list). `GET /api/v1/health` is the public health check (no session, no audit, no request log; 503 when the DB does not answer in 2 s) — the Dockerfile HEALTHCHECK and the uptime monitor use it.
Project skills: `meduza-run`, `meduza-demo-reset`, `meduza-deploy`, `meduza-verify` — use them for those tasks.

## Rules that are easy to break

- **Tenant & role come only from the server session** (`req.ctx`). Every query filters by `tenant_id`; another tenant's id must return 404, a forbidden action 403. Hiding a button is never the permission check — add the server check and a test.
- **Money is integer tiyin** (`bigint`, 1 so‘m = 100). Never sum money in floating point on the client; format with `formatSom`.
- **Time:** store UTC; display Asia/Tashkent (UTC+5, no DST). "Now" is the demo clock: SQL `demo_now()`, API `now()` from `core/clock.ts`, web `useSession().demoNow()`. Never use `now()`/`Date.now()` for business timestamps. Date filters are `[local day start, next local day start)`.
- **Writes that matter run in `db.tx`** with row locks (`FOR UPDATE`) where races are possible. Appointment overlap is enforced by a DB exclusion constraint (→ 409 `SLOT_TAKEN`); payments require `Idempotency-Key`; signed notes, verified lab results and payments are immutable via DB triggers.
- **Status changes** are validated on the server; stale client state → 409 with a "refresh" message. Audit important actions with `audit()` (no clinical text, no AI prompts in audit).
- **Clinical data is doctor-only** (managers, cashiers and registrars never read clinical notes or result values). Lab values are visible to doctors only after verification.
- **No clinical or financial data in localStorage** — only UI preferences (selected branch).
- **Errors:** API returns `{error:{code,message,fields?},request_id}`; UI keeps the user's input on failure, shows the error, and never shows a success toast for an action that did not complete.
- **Auth:** staff sign in with `/auth/login` (phone or username + scrypt-hashed password; lockout after 5 failures; temp passwords force a change — the guard returns 403 `PASSWORD_CHANGE_REQUIRED` except on routes marked `@AllowDuringPasswordChange()`). Demo role cards (`/demo/login`) only open the seed tenants. Never log, return twice, or store a password in clear text; a temp password is shown exactly once. Sessions slide: activity (guard, at most once a minute) extends `expires_at` by `SESSION_TTL_HOURS` (12) but never past `created_at + SESSION_MAX_HOURS` (14); the cookie lives `SESSION_MAX_HOURS`.
- **Telegram bot** (`apps/api/src/telegram/*`): booking rules live in `modules/booking.ts` and are shared with the staff API — never duplicate them in the bot. Patient notices go through the `notifications` outbox (`enqueueNotice` inside the event's transaction). Never send lab values, clinical text or another patient's data to Telegram; a chat sees only patients with its verified phone. Bot tokens are stored only encrypted (`core/secrets.ts`, `APP_SECRET_KEY`). Test the bot through the simulator transport or the fake Bot API in `test/telegram.test.mjs` — no real Telegram in tests.
- **Cash desk:** a payment needs the payer's *own* open shift in the invoice's branch (lock it `FOR SHARE`) — a cashier or the manager may open a shift and take money (`canTakeMoney()` in the web mirrors the server roles); a shift opened before today's local day start is stale: `/cash-shifts/current` returns `stale: true` and a payment gets 409 `SHIFT_STALE` until it is closed (Z-report = one day). Refunds are manager-only, tied to a payment, reduce the invoice (`credit_amount`, `paid_amount` stays ≤ `total`) and cash refunds/expenses must name an open shift. Revenue is cash basis and **net of refunds** everywhere (dashboard, finance summary, AI report). Shifts, refunds and expenses are append-only/void-only via DB triggers. Use `invoiceStatus()` from `billing.ts` for invoice status and `NET_LINE` for any per-service money (doctor share, service revenue) so refunds are excluded. Doctor share: `service_orders.share_percent_snapshot` is set once at order creation by `sharePercentFor()` — the performing doctor's `doctors.default_share_percent` when it is > 0 (0 = not set), otherwise the service's `share_percent`; later edits never change past orders. Cash may leave a drawer only if it is there (`INSUFFICIENT_CASH`).
- **Demo reset truncates every table** and refuses to run when a non-seed tenant exists. Real clinics belong in a separate `APP_MODE=production` deployment on a server in Uzbekistan (`Dockerfile`, `deploy/`, runbook `docs/DEPLOY_UZ.md`); there the API refuses a database with a demo clock, and the UI shows no «demo» wording (gate demo-only text on `me.demo`).
- **Hikvision cameras** (`apps/api/src/cameras/*`, `docs/HIKVISION.md`): faces and templates stay in the camera's own library; Med.uz.ai stores only our codes (`S-n` staff, `P-<patient number>` patients), event times and similarity — never face pictures or raw payloads (the parser drops image parts unread). The one exception is the **alert snapshot** (`camera_snapshots`, migration 016): the camera's picture of a *security alert* (intrusion, line crossing, region entry/exit, loitering, tamper that raised an alert), kept only when the camera's `alert_snapshots` is on, ≤ 1 MB, purged after `SNAPSHOT_DAYS` (30), readable by the manager only — never for `face_match`/`people_count` and never for a non-alert event. The demo's snapshots (`database/seed/snapshots`) are built by `tools/make-snapshots.py` from freely licensed stock photos (`tools/snapshot-sources/ATTRIBUTION.md`) with every face and sign pixelated first — never pictures from a real camera or of real patients. Staff codes need the manager's confirmation of written consent; patients need an active `biometric` consent (signed paper only). Cameras push to `POST /api/v1/hik/<token>` (only the token hash is stored). A camera can also be connected directly over ISAPI (`cameras/isapi-client.ts`, `isapi.controller.ts`, `pull-worker.ts`): Digest auth, password encrypted with `APP_SECRET_KEY`, one-click setup writes the listening host (fresh token, shown to nobody) and creates the face library, faces are forwarded to the camera from memory and never stored (`face_code_cameras` keeps only code↔camera), revoked codes are deleted from cameras by the worker, `delivery='pull'` reads `alertStream` server-side. TLS to a camera is verified (no self-signed bypass). Tests use the fake camera `test/_fakecam.mjs` — never a real device. Camera arrival is only a suggestion; accepting it runs the normal check-in. Events are append-only. Real cameras connect only to a server in Uzbekistan; the demo uses the simulator.
- **Patient consent** (`patient_consents`, `modules/consent.ts`) is append-only evidence; a withdrawal is a new row. Production requires data-processing consent when a card is created (422 `CONSENT_REQUIRED`). The consent texts are versioned (`CONSENT_TEXT_VERSION`) and need a lawyer's review — change the version when the text changes.
- **AI calls go only through `AiClient.json()`** (`apps/api/src/ai/ai-client.ts`): provider `AI_PROVIDER=anthropic` (official SDK) or `gemini` (REST generateContent), structured JSON validated with zod, refusal/error mapping, Uzbek apostrophes normalized, one `ai_usage` row per call (tokens + cost, never text). Run patient text through `redact()` first. Clinical features use `clinicalMode(tenantId)`: the Gemini free tier (`GEMINI_PAID≠1`) receives clinical text only for the seed demo tenants on a non-production deployment; every route not in `PUBLIC_ROUTES` counts as clinical. Gemini's proxy URL is `GEMINI_BASE_URL` (never `AI_BASE_URL`). AI output is a draft or a suggestion: ICD-10 codes must exist in `icd10_codes` (checked server-side); nothing is saved or signed without the doctor. Tests use the fake Claude/Gemini/PubMed servers in `test/ai.test.mjs` — never a real key.
- **i18n:** every interface string goes through `t('area.key')` (`useT()` in web; `translate()` elsewhere). Messages live in `packages/contracts/src/i18n/messages/*.ts` as `[uz, ru]` pairs (Russian plural `{one, few, many}`; optional third item overrides the automatic Cyrillic). Never hard-code UI text, never transliterate data (names, services, notes) — only interface text. Dates/ages via `lib/format.ts` helpers. The person's language comes from `/me` (saved per staff account, per session for demo cards) and the `meduza_lang` cookie before login. One 18px base for everyone; sizes in rem (`text-[0.8125rem]`, not px). `test/i18n.test.mjs` checks every pair.
- **UI building blocks:** follow `docs/UI_GUIDE.md` (one primary action per screen, ≤ 1 short subtitle line, no «next release»/explanation paragraphs on screen, 8 px spacing, capsule buttons ≥ 48 px, h-11 fields). The look is Apple-style **Liquid Glass «Clear»** (chosen 2026-10-21): glass (`.glass`, `.glass-btn`, `.glass-field` in `globals.css`, lens in `components/glass.tsx`) only on the control layer — sidebar, toolbar, phone tab bar, buttons, segmented controls; content always on opaque `.surface` cards; never glass on glass; text on glass is `slate-900`/`slate-700`. Motion is the «Prujina» spring (chosen 2026-10-22, `globals.css` «Motion»): `PressMotion` (`components/motion.tsx`, Web Animations on every button/link — never per-element classes, `data-no-press` opts out), `.page-enter` via `(app)/template.tsx`, staggered `.grid`/`tbody tr`/`.divide-y`/`.stagger` children, `.modal-panel`, `.toast-in`, `SlidingPill` (`data-active`) for the sidebar, segmented controls and the tab bar — transform/opacity only, off under `prefers-reduced-motion` (E2E runs that way); no other motion styles. Use `ui.tsx` (`PageHeader`, `StatCard`, `Money`, `Toolbar`, `EmptyState compact`, `Button`, `LinkButton` with `target`, `Field`, `Input`, `Modal` — portal, focus trap, first focus `[data-autofocus]`), `components/money-input.tsx` for any so‘m amount and `components/date-range.tsx` for periods. Check new screens at 1366×768 and 390 px in uz and ru: no clipped columns, no sideways page scroll.
- **AI:** `AI_MODE=sample` returns a pre-written result only for the exact demo text and must be labelled «Namunaviy AI natijasi»; never present it as live AI. API keys stay server-side.

- **Performance:** queries that run per page view must use an index at 100k patients / 1M appointments (see `docs/audit/load.md`, migration 015). Use `(SELECT demo_now())` or a parameter in WHERE, never unbounded «all time» scans or `LIKE '%…%'` without the trigram indexes; every list has a LIMIT; exports have a bounded period. Cash leaving a drawer locks the shift `FOR UPDATE`; read a quantity only after locking its row.

## Data & environments

- Local Postgres: docker `meduza-db` on 127.0.0.1:5433 — `meduza` = live demo shown to clinics, `meduza_test` = tests/E2E only. Tests refuse non-`_test` databases; keep it that way.
- Seed is deterministic (fixed PRNG + hashed ids). Changing RNG call order shifts seeded numbers — then update the expected KPIs in `docs/DEMO_SCRIPT.md`, `meduza-demo-reset` and tests.
- Railway (`feisty-amazement`, service `meduza` + `Postgres`, region US): password-gated demo, synthetic data only. Real patient data or biometrics must not go there — Uzbek law requires biometric data to be stored in Uzbekistan.
- Never commit or print `.env`, `backups/*.dump`, `DEMO_ACCESS_CODE`, tokens or keys.
